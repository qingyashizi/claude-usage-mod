# usage-mod

[English](README.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | **日本語**

Claude Code 用の小さな Mod です。入力欄の上に 3 つの使用量を常時表示し、ワンクリックでコンテキストを圧縮するボタンを備え、各応答のトークン使用量の折れ線グラフも展開して見られます。

![usage-mod のスクリーンショット:入力欄の上に 3 つの使用量バー、両端にアイコンボタン](docs/screenshot-bar-en.png)

(スクリーンショットは英語表示です。)左から順に、圧縮ボタン、コンテキストの使用量、5時間枠、週間枠、詳細ボタンです。右端のアイコンを押すと、バーの上にトークン内訳グラフが開きます(下の「トークン内訳グラフ」を参照)。もう一度押すと閉じます。

## 機能

- **コンテキストの使用量**:使用率とトークン数。
- **5時間枠**:使用率、リセットまでの残り時間、リセット時刻。
- **週間枠**:同上。
- **ワンクリック圧縮**:左端の線のアイコン(4 本の矢印が中央に向かう形)を押すと、そのままコンテキストを圧縮します。`/compact` と入力するのと同じ効果です。マウスを重ねるとヒントが出ます。
- **トークン内訳の展開**:右端の折れ線アイコンを押すと、バーの上に各応答のトークン使用量の折れ線グラフが開き、もう一度押すと閉じます。詳しくは下の「トークン内訳グラフ」を参照してください。
- 3 つのブロックは同じ幅で、オレンジ(`#D77757`)の塗りが使用率を表します。色は固定で、使用量によって変わりません。
- 使用量が 90% に達すると一度だけ通知します。
- 5 秒ごとに最新の値を読み取るので、応答が終わるのを待つ必要はありません。

## トークン内訳グラフ

バー右端の折れ線アイコンを押すと開き、もう一度押すと閉じます。

![usage-mod のスクリーンショット:展開したトークン内訳グラフ](docs/screenshot-chart-en.png)

展開すると、上から順に次のように並びます:

- **1 行目**:タイトル、5 項目の合計、ターン数。合計は、このセッションで Mod が記録したすべての応答を足したものです:
  - **新規入力**:キャッシュを使わず、今回新たにモデルへ送った入力トークン。
  - **出力**:モデルが生成したトークン。
  - **キャッシュ作成**:今回新たにプロンプトキャッシュへ書き込んだトークン。
  - **キャッシュ読取**:プロンプトキャッシュから読み出したトークン。新たに送るよりずっと安価です。
  - **キャッシュヒット率**:キャッシュ読取 ÷(新規入力 + キャッシュ作成 + キャッシュ読取)。
- **2 行目**:4 本の線の切り替えです。凡例の名前を押すと、対応する線を表示 / 非表示にできます。キャッシュ読取はたいてい他の 3 項目より何桁も大きく、同じ縦軸では他の線が底に張り付いてしまいます。キャッシュ読取を隠すと、残りの増減が見えるようになります。
- **折れ線グラフ**:応答 1 回につき 1 点、横軸は時間順(左下と右下に最も古い時刻と最新の時刻)、縦軸はトークン数です。直近 50 ターンまで保持します。
- **マウスをあるターンに重ねる**:その列が強調表示され、横に半透明の詳細カードが出ます:開始時刻 → 終了時刻、所要時間、モデル、そのターンの 4 項目の数値。サブエージェントの応答にはモデル名の後ろに印が付きます。

知っておくべき点:

- データは**現在のセッション**のものだけで、Mod が**読み込まれた後**の応答だけを記録します。再起動や `/reload-plugins` の後は一から集計し直し、ファイルには保存しません。
- 「所要時間」は実時間です。入力待ちで止まっていた時間も含まれるため、1 時間席を外して戻ると、そのターンは 1 時間以上と表示されます。開始時刻は「終了時刻 − 所要時間」で逆算しています。
- グラフは画像を描画できる画面(デスクトップアプリ)でのみ表示されます。ターミナルでは展開ボタンを押しても合計の数字しか見えず、折れ線グラフはありません。
- カードは「列」単位で動き、マウスポインターに本当に追従するわけではありません。この種のグラフ内ではスクリプトを実行できず、マウスの正確な位置が取れないためです。
- 展開中、グラフがときどきちらつくことがあります。ホバーに反応するグラフは専用の小さなウィンドウの中に描く必要があり、バーが再描画されるたび(応答中に数字が変わるときなど)にそのウィンドウが作り直されるためです。ちらつきを減らすため、展開中は 1 分ごとのカウントダウン更新を止めており、閉じると反映されます。
- ウィンドウが狭くて 1 行目に収まらないときは、タイトル、次に「N ターン」を 2 行目へ移動、さらに合計のキャッシュヒット率と新規入力の順に省きます。4 つの言語は文字の長さが大きく違うため、現在の言語の実際の文字幅で計算しています。
- このグラフには「各ターンが 5時間枠の何 % を使ったか」は表示しません。エンジンが返すのは整数のパーセントだけで、しかもアカウント全体で共有です(他のセッションや Web 版で使った分も含まれます)。ターンごとに引き算しても意味がありません。
- ボタンの線のアイコンは [Lucide](https://lucide.dev)(ISC ライセンス)のものです。

## 言語

**簡体字中国語(`zh`)、繁体字中国語(`zh-TW`)、English(`en`)、日本語(`ja`)** に対応しています。

既定(`auto`)ではパソコンの言語に合わせます。簡体字中国語のパソコンでは簡体字中国語、繁体字中国語(台湾・香港・マカオ)のパソコンでは繁体字中国語、日本語のパソコンでは日本語、それ以外は英語で表示します。

特定の言語に固定するには、Claude Code で `/plugin` を実行して usage-mod を開き、**Language / 语言** を変更します。または `~/.claude/settings.json` に次のように設定します:

```json
{
  "pluginConfigs": {
    "usage-mod": { "options": { "language": "en" } }
  }
}
```

変更後、モジュールは自動的に再読み込みされます。`auto` を選んだ場合、設定がない場合、言語コードが間違っている場合は、いずれもパソコンの言語に従います。(マーケットプレイスからインストールした場合、`pluginConfigs` のキー名は `/plugin` に表示されるものに従ってください。`/plugin` の画面で直接変更するのがいちばん確実です。)

別の言語を追加するには、`hooks/i18n.ts` を開き、辞書を 1 つコピーして翻訳し、`DICTS` に登録してから、言語コードを `.claude-plugin/plugin.json` の `userConfig.language.options` に追加します。

## 必要なバージョン

Mod には **Claude Code 2.1.287 以降**が必要で、このバージョンから既定で有効です。`claude --version` で確認できます。

この Mod は 2.1.286 で開発したため、2.1.286 以前のバージョンでは環境変数 `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1` の設定が別途必要です(下の「手動で読み込む」を参照)。2.1.287 以降ではこの変数は無視されるので、設定は不要です。

## インストール

### 方法 1:マーケットプレイスからインストール

**以下のコマンドはターミナルで実行してください。** Claude Code のチャット欄に入力するものではありません。ターミナルは、PowerShell や Windows Terminal(macOS / Linux では標準のターミナル)、またはデスクトップアプリの会話の横にある Terminal パネルのいずれでも構いません。

```bash
claude plugin marketplace add qingyashizi/claude-usage-mod
claude plugin install usage-mod@usage-mod
```

- 1 行目:GitHub の `qingyashizi/claude-usage-mod`(形式は `ユーザー名/リポジトリ名`)を「プラグインマーケットプレイス」、つまりプラグインを選べる一覧として Claude Code に登録します。登録するだけで、**まだ何もインストールされません**。
- 2 行目:いま登録したマーケットプレイスからプラグインをインストールします。`usage-mod@usage-mod` は `プラグイン名@マーケットプレイス名` の形式で、ここでは偶然どちらも同じ名前です。前がプラグイン、後ろがマーケットプレイスです。

すでに開いているセッションでは `/reload-plugins` を実行して読み込みます。そうでなければ次回の起動時に有効になります。

### 方法 2:手動で読み込む

まず `usage-mod` フォルダ全体を好きな場所に置きます(例:`~/.claude/mods/usage-mod`)。

**一時的に試す**(その起動のときだけ有効):

```bash
claude --plugin-dir ~/.claude/mods/usage-mod
```

**ずっと使う**:`~/.claude/settings.json` に `env` ブロックを追加し、パスを自分の環境に合わせます。新しく開いたセッションから読み込まれます。

```json
{
  "env": {
    "CLAUDE_CODE_PLUGIN_DIRS": "C:\\Users\\あなたのユーザー名\\.claude\\mods\\usage-mod"
  }
}
```

2.1.286 以前のバージョンでは、`env` に `"CLAUDE_CODE_ENABLE_FUNCTION_HOOKS": "1"` も追加してください。コードを変更したときに再起動せず反映させたい場合は、さらに `"CLAUDE_CODE_PLUGIN_DIR_WATCH": "1"` を追加します。

### インストール前に何をするか確認する

Mod は Claude Code の中であなたの権限で動くコードで、サンドボックスはありません。インストール前に、どのイベントに反応し、どの機能を呼び出すかを一覧できます:

```bash
claude plugin validate ./usage-mod
```

出力の `hooks:` と `calls:` の 2 行が答えです。この Mod が使うのは次のとおりです:使用量の読み取り(`$.session.usage`)、応答が終わるたびにそのターンの使用量を記録(`turn.complete` イベント。読み取り専用で、メモリ上にだけ保持)、コンテキスト圧縮のための `/compact` コマンドの実行(`$.command.run`)、自分のフォルダ内の `cache/limits.json` の読み書き(`$.fs.read` / `$.fs.write`)、通知の表示(`$.ui.toast`)、タイマー(`$.clock`)。ネットワークには接続せず、他のファイルも読みません。

### 動作する場所

- ターミナルの `claude`:バーと圧縮ボタンは表示されます。**トークン内訳の折れ線グラフは表示されません**(ターミナルでは画像を描けないため)。展開ボタンは文字の記号に置き換わり、開いても合計の数字だけです。
- デスクトップアプリの Code タブ:バー、2 つのボタン、折れ線グラフのすべてが表示されます(WSL セッションではプラグインは使えません)。
- VS Code 拡張、`claude -p`、クラウドセッション:Mod は動作しますが、バーは表示されません。

## カスタマイズ

色、アイコン、折れ線グラフのスタイルなどは `hooks/register.tsx` の先頭にある定数に、表示される文字(ホバーのヒント `tip` を含む)は `hooks/i18n.ts` にあります:

| 定数 | 役割 |
|---|---|
| `ORANGE` | 使用済み部分の塗りの色 |
| `WARM` | 残り部分の背景色 |
| `DARK` / `LIGHT` | 塗りの内側 / 外側の文字色 |
| `ICON_PATHS` | 2 つのボタンの線のアイコン(Lucide の図形データ)。アイコンを変えるにはここの図形を差し替えます |
| `ICON_BG` / `ICON_LINE` | アイコンの背景色(バーの背景と同じにする)と線の色 |
| `ICON` | 画像要素のない画面(ターミナル)で、圧縮ボタンに使う文字の記号 |
| `SERIES` | 折れ線グラフの 4 本の線の色 |
| `CARD` / `GRID` / `MUTED` | 折れ線グラフの背景色、グリッド線、軸の文字色 |
| `TIP_BG` | ホバーで出る詳細カードの背景色 |
| `MAX_TURNS` | 記録するターン数の上限。既定は 50 |
| `WARN` | 通知を出すパーセントのしきい値。既定は 90 |

## 既知の制限

- **Mod のインターフェースは現時点で早期アクセス**で、Claude Code のバージョンによって変わります。この Mod は 2.1.286 で開発・テストしており、他のバージョンでは読み込みに失敗したり表示が崩れたりすることがあります。
- **起動後まだ開いていないセッションに切り替えると、バーが表示されるまで数秒かかります。**実測(デスクトップアプリ、Claude Code 2.1.289、十数回)で 2.5〜5.5 秒、平均約 4 秒です。一度開いたセッションに戻る場合は即時です。この時間はほとんどエンジン内部で費やされ、Mod では制御できません。Mod の読み込み完了から起動フック開始までが約 1 秒、起動フック終了からバーが最初に描画されるまでが約 1.7 秒で、Mod 自身の初期化は 1 秒未満です。初期化をブロックしない形にも試しましたが、所要時間に明確な変化はありませんでした(平均 4.3 秒と 4.0 秒で、ばらつきの範囲内)。
- **5時間枠と週間枠は、このプロセスで一度応答を受け取った後でないと実際の値になりません。**新しいセッションではまず前回保存したデータ(mod フォルダ内の `cache/limits.json`)を表示し、すでにリセット時刻を過ぎたものは破棄して「—」と表示します。これはエンジンのデータの渡し方によるものです。
- **バー背景の上下の余白はアプリ側のもの**で、Mod では変更できません。
- デスクトップアプリでは、ホバーのヒントはアプリが暗いカードとして描くため、文字は明るい色にしています。ターミナルではオレンジの地に暗い文字です。
- ウィンドウが 78 桁より狭いと、短い 1 行の文字表示に切り替わります。このとき 2 つのボタンはなく、内訳グラフも開けません。
- 折れ線グラフの幅はバーのセル数から見積もっています(画像はピクセル幅しか受け付けず、エンジンはバーが実際に何ピクセルあるかを Mod に教えません)。大きく見積もりすぎるとアプリが画像全体を縮小して背景色が見え、小さすぎると左右の余白が増えます。フォントサイズによっては `CHART_PX_PER_CELL` の調整が必要かもしれません。
- 圧縮はそれまでの会話を要約に置き換えるため、詳細は失われます。**押すとすぐに実行され、確認はありません。**
- **圧縮はモデルが会話を要約するのを待つため、コンテキストが大きいと時間がかかります。**実測では約 41 万トークンで 63 秒でした。押すと「コンテキストを圧縮中…」と出て、完了すると「コンテキストを圧縮しました」と出ます。途中に進捗表示はないので、繰り返し押さないでください。
- デスクトップアプリのセッションは SDK(ヘッドレス)セッションで、エンジンは Mod が圧縮インターフェース(`$.session.compact`)を直接呼ぶことを許しません。そのためボタンは、代わりに `/compact` コマンドを実行する(`$.command.run`)方法を取っています。この方法はデスクトップアプリでのみ確認しており、ターミナルでは試していません。
- AI が応答中にボタンを押した場合:エンジンのドキュメントによれば、コマンドは待ち行列に入り、そのターンが終わってから実行されます。この点は自分では確認していません。
- 作者はローカルで `--plugin-dir` と `CLAUDE_CODE_PLUGIN_DIRS` を使った動作のみ確認しています。マーケットプレイス経由のインストールは公式ドキュメントに従って書いたもので、自分では試していません。

## アンインストール

**マーケットプレイスからインストールした場合**(こちらもターミナルで実行):

```bash
claude plugin uninstall usage-mod@usage-mod
```

すでに開いているセッションでは `/reload-plugins` を実行してください。そうでなければ次回の起動時に反映されます。Claude Code で `/plugin` を実行し、一覧の usage-mod から操作することもできます。一時的に無効にして後でまた使いたいときは `claude plugin disable usage-mod@usage-mod` を使います(あとで `enable` で戻せます)。

追加したマーケットプレイスも削除するには:

```bash
claude plugin marketplace remove usage-mod
```

**手動で読み込んだ場合:** `settings.json` の `CLAUDE_CODE_PLUGIN_DIRS` の項目を削除(またはパスを変更)し、フォルダを削除すれば完了です。

言語を変更した場合、`settings.json` の `pluginConfigs` に `usage-mod` の項目が残っていることがあります。動作には影響しませんが、きれいにしたければ手で削除してください。
